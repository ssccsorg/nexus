# Ward Insulin Line
#
# An insulin pump runs the same firmware for ten years on an 8-bit MCU: no operating system, no
# database, 32 KB of flash. It keeps its own record and reads it, which is what lets it reduce a
# dose instead of sounding an alarm it would have to explain.
#
# A clinic's ward writes here: three pumps log the glucose they acted on and the dose they gave,
# three monitors log the same glucose from the other side of the loop, a patch sensor logs the trend
# the others are compared against, and the clinic's two consoles read the record at the next visit,
# which is a program keeping the appointment. The pumps are the only devices here that change
# anything, and each keeps its own account of what it did.
#
# Run it on this host:
#
#   demo-sim apps/demo-sim/scenario/pump.txt /tmp/pump-volume --reset

seed 11

# One reading an hour from every monitor on the ward.
tick 0
write 6 32 cgm-sensor-1/glucose 3600
write 6 32 cgm-sensor-2/glucose 3600
write 6 32 cgm-sensor-3/glucose 3600
count 18

write 6 32 patch-sensor-4/glucose 3600
count 24

# And the dose that went with it, from each pump.
write 6 24 insulin-pump-1/dose 3600
write 6 24 insulin-pump-2/dose 3600
write 6 24 insulin-pump-3/dose 3600
count 42

# The same slope it has seen before, and the reading it is looking at now.
tick 604800
fact slope-last-tuesday 48 insulin-pump-1/glucose
fact slope-now 48 insulin-pump-1/glucose
count 44

# What bounded the judgement: the low it must keep the patient above, and the dose it may change.
hint dose-bounds low=3.9mmol,dose=0.05u

# The work the pump declares, from the reading it found it in. The taker is the pump itself, which
# is the shape a device that acts on its own has: the same chain, with one name in two places.
intent reduce-dose slope-now hold-the-low
claim reduce-dose insulin-pump-1
fact dose-given 48 insulin-pump-1/dose
count 45
conclude reduce-dose dose-reduced
count 46

# The ward declares more than the one dose, and the clinic's consoles keep their own appointment with
# the record: one piece of work the first console has taken, and one still waiting for whoever is free.
intent log-visit dose-given note-the-dose
claim log-visit care-console-1
intent review-trend slope-last-tuesday compare-with-last-tuesday

flush

# The pump reads the new fact and the low did not arrive: no alarm was recorded, because none was
# needed, and the record is what says so.
tick 1440
fact settled 48 insulin-pump-1/glucose
count 47

# The next visit, and the consoles keep what the clinicians read.
tick 86400
write 2 32 care-console-1/review 3600
write 2 32 care-console-2/review 3600
count 51

# The rest of the ward keeps its own account too: the monitors beside the patient, the second
# delivery fleet, the ventilator, the meter that reads the same glucose by another route, and the
# gateway that carries nothing off the ward. They are here because a ward is not one device: the
# record each of them keeps is what the others are compared against, and none of them asks a
# server what the patient is doing.
tick 3600
write 4 32 bedside-monitor-1/vitals 3600
count 55
write 4 32 bedside-monitor-2/vitals 3600
count 59
write 4 24 syringe-driver-1/dose 3600
count 63
write 4 24 syringe-driver-2/dose 3600
count 67
write 3 24 ventilator-1/settings 3600
count 70
write 3 32 glucose-meter-5/glucose 3600
count 73
write 5 16 ward-gateway-1/forward 3600
count 78

flush

query 0 900000 * 78
